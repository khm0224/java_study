- 주요 컴포넌트
Controller (GuestbookController): 클라이언트의 요청(URL)을 가장 먼저 받아 처리하고,
비즈니스 로직 호출 후 결과를 전달합니다

Service / ServiceImpl (GuestbookService, GuestbookServiceimpl): 핵심 비즈니스 로직을 수행합니다. 데이터베이스와 소통하기 위해 Repository를 호출하고, DTO와 Entity 간의 변환을 담당합니다

Repository (GuestbookRepository): Spring Data JPA를 활용해 데이터베이스(MariaDB 등)와 상호작용하며, 기본 CRUD 및 QueryDSL을 지원합니다

Entity (Guestbook, BaseEntity): 실제 데이터베이스 테이블과 매핑되는 도메인 객체이며, BaseEntity를 통해 등록일(regDate)과 수정일(modDate)을 자동으로 관리합니다

DTO 및 페이징 객체 (GuestbookDTO, PageRequestDTO, PageResultDTO): 화면과 계층 간 데이터 교환 및 페이징/정렬 처리를 담당합니다

- 실행 순서

<1> 목록 조회 요청 흐름 (/list)
1. 클라이언트 요청 (GuestbookController)
사용자가 웹 브라우저에서 / 또는 /list 주소로 접속하면 GuestbookController가 요청을 수신합니다

2. 서비스 계층 호출 (GuestbookServiceimpl)
컨트롤러의 위임을 받아 비즈니스 로직이 실행됩니다
PageRequestDTO를 기반으로 정렬 조건(예: 글 번호 gno 기준 내림차순)과 페이지 정보가 담긴 Pageable 객체를 생성합니다

3. 데이터베이스 조회 (GuestbookRepository)
guestbookRepository.findAll(pageable)을 호출하여 DB에서 페이징 처리된
Page<Guestbook> 엔티티 목록을 가져옵니다

4. DTO 변환 및 결과 포장 (PageResultDTO)
조회된 엔티티 각각을 entityToDto 메서드를 통해 GuestbookDTO로 변환합니다
변환된 리스트와 페이지네이션 계산 결과(시작/끝 페이지, 이전/다음 버튼 여부 등)를 PageResultDTO에 담아 반환합니다

<2> 방명록 등록 요청 흐름 (Register)
1. 클라이언트 입력
사용자가 방명록 작성 폼에 제목, 내용, 작성자를 입력하고 전송합니다

2. 서비스 계층 처리 (GuestbookServiceimpl)
전달받은 GuestbookDTO 객체를 로그 등으로 확인한 뒤,
dtoToEntity() 메서드를 이용해 Guestbook 엔티티 객체로 변환합니다

3. 데이터 저장 (GuestbookRepository)
guestbookRepository.save(entity)를 호출하여 DB에 새로운 방명록 데이터를 INSERT합니다
저장이 완료되면 생성된 고유 번호(gno)를 반환합니다
